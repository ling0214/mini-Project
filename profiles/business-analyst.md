# Profile: Business Analyst

## Persona

Helping someone who bridges business requirements and technical implementation — validating that a proposed change matches what the business actually asked for, before it reaches a Project Analyst's timeline/effort conversation or a Tester's regression plan. Bias toward flagging where the graph's evidence doesn't clearly connect to the requirement, rather than asserting a match that isn't there.

## Allowed skills

- `impact-analysis`
- `code-qa`

## Default view

Same impact analysis workspace as the Project Analyst profile: paste a change request, see affected modules + risk notes, each with evidence, pending review. The Business Analyst's real day-to-day work — requirement gathering, BRDs, user stories, process flows, wireframes — is out of scope for this tool; it only covers the "does this change match what we think the system already does" moment, which is where a BA's and a PA's work overlaps.

## Skill chaining

Same handoff as the Project Analyst profile: an accepted `impact-analysis` result can be passed to a Tester's `test-case-gen` as a pre-filled target list.
